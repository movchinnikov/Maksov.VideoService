# Agent permissions: what is allowed without asking, what only on request

This rule defines the **boundaries** for autonomous work in this repository. The same boundaries are duplicated in `.claude/settings.json` (for Claude Code); in Antigravity, command permissions are granted by the user in the confirmation dialog ("Always allow" by command prefix) — the agent does not grant them to itself and does not bypass them.

## Allowed without asking
| Area | What is allowed |
| --- | --- |
| Files | Read and edit everything inside the repository (except `.env` — read only, do not copy secrets into answers or documents). Create directories and files, move, rename. |
| Docker | `docker`, `docker compose` (build, run, logs, `exec`, `cp`, `ps`, `images`, `pull` of version-pinned images), `make up/down/test/lint/pack/demo/verify-auth/up-ml/logs`. Project containers only (`videoservice-*`), project volumes only. |
| Build and tests | `dotnet`, `npm`/`npx`/`node`, `python3` (`scripts/` scripts), `mvn` inside `docker build`, `ffmpeg`/`ffprobe` locally. |
| curl | To the local stack: `http://localhost:*` and `http://127.0.0.1:*` (gateway 8081, Keycloak 8080, MinIO 9000/9001, Ollama 11434, web 3000). To package and image registries for builds: `api.nuget.org`, `registry.npmjs.org`, `repo1.maven.org`, `hub.docker.com`, `quay.io`, `mcr.microsoft.com`. Nothing else. |
| git (read) | `git status`, `git diff`, `git log`, `git add` (after checking private paths). |

## Only on explicit user request
- `git commit`, `git tag`, `git push` (push — never without a request; no traces of AI in commits and tags: no `Co-Authored-By`, "generated by").
- Deleting data outside project volumes, `docker system prune`, `docker volume rm` of foreign volumes, `rm -rf` outside `bin/obj/node_modules/dist/artifacts`.
- Any access to external services not listed above (clouds, SaaS, foreign hosts), downloading code from the network and running it (`curl … | sh`).
- Changing settings of the agent/IDE/sandbox itself and files outside the repository.

## Never
- Bypass the sandbox, confirmation prompts and access policies; spoof identity; touch state that access checks read.
- `sudo`, `--privileged`, mounting `/` or `docker.sock` into containers, `--network host`.
- Attack or scan anything other than the project's local stack (pentest only against the `make up` stack).
- Commit secrets, `.env`, `.agents/`, `.claude/`, `CLAUDE.md`, `AGENTS.md`, `private/`, `docs/runs/`, `docs/reviews/`.
- Solve CAPTCHAs and "verify you are human" checks (report to the user and stop).

## How to check
Before any command with a side effect outside the repository or over the network, check against the table. When in doubt, ask the user.
