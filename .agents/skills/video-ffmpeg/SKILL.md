# Video / FFmpeg

## Input / output
- **Input:** a transcoding job (`video_id`, source key).
- **Output (MinIO `videos/{video_id}/`):**
  - `stream/manifest.mpd` — DASH;
  - `stream/master.m3u8` + `stream/media_N.m3u8` — HLS;
  - `stream/init-N.m4s`, `stream/chunk-N-XXXXX.m4s` — **shared CMAF segments** for both protocols;
  - `poster.jpg`.
- Status `Ready` (with duration, dimensions, list of renditions) or `Failed(reason_code)`.

## Why CMAF
One set of fMP4 segments serves both DASH and HLS → encode once, store once (2× savings in CPU and disk compared with separate TS + fMP4).

## Input validation (ffprobe before transcoding)
- `ffprobe -v error -print_format json -show_format -show_streams` with a timeout.
- Allowlist of containers/codecs; duration ≤ limit; resolution ≤ 4K; fps ≤ 60; file size ≤ limit.
- "Video bomb" protection: a limit on `width*height*fps*duration`, a limit on the number of streams, timeouts.
- Rotation (`side_data` displaymatrix) — ffmpeg auto-rotates; compute dimensions **after** rotation. Vertical video is scaled by the short side.
- No audio → the adaptation set is video only (do not fail).

## Ladder (H.264 High + AAC-LC, reference)
| Short side | maxrate | bufsize | Audio |
| --- | --- | --- | --- |
| 240 | 400k | 800k | 64k |
| 360 | 800k | 1600k | 96k |
| 480 | 1400k | 2800k | 128k |
| 720 | 2800k | 5600k | 128k |
| 1080 | 5000k | 10000k | 160k |
Do not upscale beyond the source (there is always at least one rung). Width/height are even.

## Command (single pass, single decode)
```
ffmpeg -hide_banner -nostdin -y -i in.mp4 \
  -filter_complex "[0:v]split=N[v0]...;[v0]scale=W0:H0[o0];..." \
  -map [o0] -c:v:0 libx264 -b:v:0 ... -maxrate:v:0 ... -bufsize:v:0 ... \
  ... -map 0:a:0? -c:a aac -b:a 128k -ac 2 \
  -preset veryfast -profile:v high -pix_fmt yuv420p \
  -g 2*fps -keyint_min 2*fps -sc_threshold 0 \
  -f dash -seg_duration 4 -use_template 1 -use_timeline 0 \
  -hls_playlist 1 -hls_master_name master.m3u8 \
  -init_seg_name 'init-$RepresentationID$.m4s' -media_seg_name 'chunk-$RepresentationID$-$Number%05d$.m4s' \
  -adaptation_sets "id=0,streams=v id=1,streams=a" \
  -threads T -progress pipe:1 out/manifest.mpd
```
- Keyframes are aligned across renditions (fixed GOP, `-sc_threshold 0`) — without this, ABR switching breaks the picture.
- Loudness (lesson 3+): `loudnorm` I=-16 (two-pass — only if the CPU budget allows).
- Poster: `-ss min(1, dur/2) -frames:v 1 -q:v 3 poster.jpg`.

## Running from .NET
- `Process` with `ArgumentList` (no string concatenation → no injection), `-progress pipe:1` → progress metric, `stderr` goes to the log (tail).
- Timeout ∝ duration (e.g., 5× duration + 60 s), `Kill(entireProcessTree: true)` on cancellation.
- Limits: `-threads`, container limits, `MaxConcurrentJobs` (default 1).
- Working directory `/tmp/work/{video_id}` on `tmpfs`/volume; the source is streamed from MinIO to a file; results are uploaded with bounded parallelism; cleanup in `finally`.

## Idempotency
- Deterministic keys; on retry — overwrite; the readiness marker is the `Ready` status in the DB, set **after** all objects are uploaded.
- A job for `Ready` → no-op. Lease expired (worker died) → another worker takes the job.

## Current layout (after the move to services)
- **Priority is vertical video (9:16)**, horizontal is supported (ADR 0007). The ladder is by the **short side** (240p … 1080p), without upscaling; a vertical 720×1280 gives "720p". Test videos and the demo are vertical.
- **SAR and DASH:** phone sources often have no SAR; after rounding to even dimensions the rung proportions diverge and DASH fails with "Conflicting stream aspect ratios". If the source has no SAR, `setsar=1` is added before `split`; if it has one, it is preserved. Tests: `FfmpegArgsBuilderTests` (`Source_without_sar_gets_square_pixels_before_split`, `Source_with_sar_keeps_it`), `FfprobeParserTests.Detects_whether_source_has_sar`.
- **Outbox from the worker:** on `ready`, `video.processed.v1` is written in the same transaction; `OutboxDispatcher` (`Videos.MediaWorker`, videos solution) delivers it to the analysis and comments subscribers; on video deletion — `video.deleted.v1`.
- **Analysis tools** (the `analysis` service, `Analysis.Worker`, a separate image with ffmpeg; nothing is encoded, only measured): one pass over a downscaled video — `fps=4,scale=-2:180,select='gte(scene,0)',signalstats,metadata=print` (shot changes, brightness, saturation, hue, YDIF motion) and one over the audio — `volumedetect`, `silencedetect=n=-45dB:d=0.5`. Always `-protocol_whitelist file`. `DescriptionComposer` builds the description text and tags; missing measurements are skipped, not invented. Parsers — `StatsParsers`, tests — `FfmpegInspectorTests`, `StatsParsersTests`.
