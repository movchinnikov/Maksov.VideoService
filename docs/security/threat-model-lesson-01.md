# Threat model: lesson 1 (upload, transcoding, playback)

> State at the git tag `lesson-01`. The `friends` and `feed` services and pgvector are covered in [threat-model-lesson-02.md](threat-model-lesson-02.md).

Trust boundaries: browser ↔ web/gateway, gateway ↔ services (videos, users, analysis, comments), media-worker → analysis and comments (outbox, internal HTTP), videos → users (following list for the feed), browser ↔ MinIO (presigned), browser ↔ Keycloak, services/workers ↔ Postgres (own DB per service) and MinIO, workers ↔ ffmpeg (untrusted input). Architecture — [ADR 0006](../adr/0006-microservices-gateway-videos-users-analysis.md).

| # | STRIDE | Threat | Mitigation | Verification |
| --- | --- | --- | --- | --- |
| T1 | Spoofing | Forged/foreign JWT, `alg=none`, HS256 with the public key | RS256 only, `iss`, `aud`, `exp`, keys from Keycloak JWKS | `KeycloakAuthExtensions` config |
| T2 | Elevation | IDOR: reading/complete/streaming another user's video | Owner only from `sub`; all queries filter by `owner_id`; foreign → 404 | `AC_auth_01`, `AC_watch_02` |
| T3 | Tampering | Uploading a different type/size than declared | Content-Type in the URL signature; `HEAD` and size check before enqueueing; ffprobe + format allowlist | `AC_upload_02/03`, `MediaPolicyTests` |
| T4 | DoS | Video bomb (huge resolution/duration/stream count) | Limits on size, duration, resolution, streams; ffmpeg timeout; container limits; 1 task per worker | `MediaPolicyTests` |
| T5 | Info disclosure / SSRF | HLS/concat playlist file with external URLs | `-protocol_whitelist file` for ffprobe/ffmpeg; container allowlist | `Text_file_with_mp4_extension_is_rejected` |
| T6 | Info disclosure | Path traversal in `/stream/{file}` | Flat name, character and extension allowlist, key built by the server | `AC_security_01`, `MediaKeysTests` |
| T7 | DoS | Mass creation of uploads | Rate limit 20/min per user at the gateway (`create-upload` policy); presigned TTL 15 min | `GatewayTests.AC_gateway_05_*` |
| T8 | Info disclosure | Token leak via XSS / storage | Tokens in memory; CSP without inline scripts; React escapes output | `nginx.conf`, `auth.tsx` |
| T9 | Tampering | ffmpeg argument injection | `ArgumentList`, no shell; paths generated by the server | `ProcessRunner` |
| T10 | Elevation | Worker compromise via an ffmpeg vulnerability | Non-root, read-only rootfs, separate container, limits; (lesson 13: NetworkPolicy with no egress) | compose |
| T11 | Info disclosure | Secrets in the repository | `.env` outside git, `.env.example` with placeholders; IdP secrets only via `make idps` | `.gitignore` |
| T13 | Spoofing / Info disclosure | Phone number enumeration (user enumeration), registering someone else's number | Same response for a wrong password and an unknown number; number is unique (`phone-unique`); Keycloak brute-force protection by username; **no SMS confirmation** (residual risk, ADR 0005) | `scripts/verify-auth.py` |
| T12 | Spoofing | Linking an external account by an unverified e-mail | `trustEmail` only for Google; Microsoft — no auto-linking | `configure-idps.sh` |
| T14 | Spoofing / Elevation | Forged inter-service call: a foreign client sends an event to `analysis` | Internal endpoints protected by the `X-Internal-Key` key (`INTERNAL_API_KEY`), constant-time comparison; empty key in config = endpoint closed; key only from the environment | `DescriptionsApiTests.AC_analysis_01_*`, `AC_comments_07_*`, `AC_users_10_*` |
| T15 | Elevation | Direct access to services bypassing the gateway (address guessing, routing error) | Ports of `videos`, `users`, `analysis`, `comments` are not published to the host (only gateway :8081 and web :3000 are exposed); each service validates the JWT itself (zero trust); `/internal/**` is not routed at the gateway (404) | `GatewayTests.AC_gateway_03_*`, `AC_gateway_01_*`, demo, compose |
| T16 | Tampering / Repudiation | Duplicate or replayed event, content substitution | Idempotent intake by `video_id`; validation of `schemaVersion`, `eventId`, `ownerId`; at-least-once delivery via outbox with backoff; channel protected by a key | `DescriptionsApiTests.AC_analysis_02/03_*`, `OutboxTests` |
| T17 | Info disclosure / SSRF | Foreign or arbitrary `sourceKey` in the event: analysis-worker reads another's object or an internal resource | `sourceKey` is accepted only if it equals `uploads/{videoId:N}/source` (the key is built by a single `MediaKeys` rule); the worker reads only from the MinIO bucket by key, not by URL | `DescriptionsApiTests.AC_analysis_03_*`, `MediaKeysTests` |
| T18 | Info disclosure | Data leak between services via a shared DB | DB-per-service: each service has its own DB and role (`00-databases.sh`), different passwords (`VIDEOS_/USERS_/ANALYSIS_/COMMENTS_DB_PASSWORD`); a role has no access to another DB; own migrator | per-service temporary DBs (`TestDatabases` from `TestSupport`), compose |
| T19 | Tampering / DoS | Queue hijacking by a worker: two workers process one task, a "stuck" lock | `SKIP LOCKED` + lease (`locked_until`, `locked_by`); an expired lease is reclaimed, the "old" worker cannot finish the task; attempt limit (`max_attempts`) | `AnalysisAdapterTests.Expired_lease_is_reclaimed_and_stale_worker_cannot_finish`, `PostgresAdaptersTests` |
| T20 | Info disclosure | Someone else's unfinished description | The owner sees any description status, others only `done` (otherwise 404); text is returned only when `done` | `AC_analysis_05`, `AC_analysis_07` |
| T21 | DoS / Elevation | analysis-worker compromise (ffmpeg on an untrusted file) | Separate image and container, read-only rootfs, limits 1 CPU / 768 MB, no inbound ports; analysis failure does not affect the video | compose |
| T22 | Info disclosure | Visibility of ready videos: any authenticated user sees others' `ready` videos, stream, poster, feed | Deliberate decision ([ADR 0009](../adr/0009-social-features-comments.md)): no anonymous access (JWT at the gateway and in the service); unready, failed, and deleted videos — owner only, 404 for others; no private accounts — residual risk | `AC_watch_02`, `AC_auth_01`, `AC_delete_01` |
| T23 | Elevation | Comment IDOR: deleting someone else's comment, commenting on a nonexistent or deleted video | Author taken from `sub`; the comment author or the video owner can delete (owner — from the `known_videos` replica); otherwise 404, indistinguishable from nonexistent; the video must be known to the service and not deleted | `AC_comments_02`, `AC_comments_06` |
| T24 | Elevation / Spoofing | Following or editing "on behalf of another", self-follow, deleting someone else's video | Follower and owner only from `sub`, not from the body or path; self-follow forbidden in the API and by a DB CHECK; video deletion — owner only (foreign → 404) | `AC_users_06`, `AC_users_08`, `AC_delete_01` |
| T25 | Tampering / DoS | Delete cascade: a forged or late `video.deleted.v1` / `video.processed.v1` erases data or resurrects deleted items | Events accepted only with `X-Internal-Key` (T14); idempotent by `video_id`; in comments a deleted video is a "tombstone", a late `processed` does not resurrect it; MinIO cleanup — only prefixes by `videoId` (GUID, built by the server); residual risk — a leaked internal key allows deleting data | `AC_comments_07/08`, `AC_analysis_08`, `CommentsAdapterTests.Forgetting_a_video_removes_comments_and_blocks_resurrection`, `OutboxTests` |
| T26 | DoS | Feed: a huge following list, frequent following-list requests to users | List is bounded (users — up to 5000 ids, feed — up to 2000 authors), keyset pagination, page ≤ 30, following cache 20 s; users unavailable → degrade to own videos instead of an error | `AC_feed_01` |
| T27 | Info disclosure | People search as a user directory (username enumeration) | Authenticated users only; prefix search, query ≤ 60 characters, results ≤ 50, wildcard characters escaped; the caller is not in the results. Residual risk: any authenticated user can enumerate prefixes | `AC_users_09`, `UsersAdapterTests.Search_matches_prefix_ignores_case_escapes_wildcards_and_marks_following` |
| T28 | Tampering / Info disclosure | Comment content: XSS, overly long text, spam | Text is trimmed at the edges, length ≤ 500, stored as text; the web client renders via React (escaping), CSP without inline scripts; there is no rate limit for comments — residual risk | `AC_comments_03/04` |
| T29 | Info disclosure | Stale `owner_username` snapshot in the feed | The username is public and reflects the value at upload time; access rights do not depend on it (only `owner_id` from `sub`) | `AC_feed_01` |

## Residual risks
- The dev client `videoservice-cli` with password grant — local only; remove in any non-local environment.
- Keycloak `start-dev` and HTTP — acceptable locally; TLS — lesson 13.
- The inter-service key is shared by all services and sent over HTTP inside the compose network; in k8s — separate keys/mTLS (lesson 13).
- The visual model (Ollama, `ml` profile) receives user frames only locally; the model and its responses are untrusted input: the caption is added as text, without execution.
- Any authenticated user sees ready videos, profiles, and the user directory; private accounts and blocking are not implemented (a separate ADR if needed).
- Rate limit at the gateway only for upload creation; comments and follows are not rate-limited.
- No antivirus scanning of uploads (out of scope; if needed — a ClamAV worker).
